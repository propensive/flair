# `D2` — Lambda bracketing

**Principle:** D — Density

Raised by flair when the house-style rule on lambda bracketing is broken.

## Cause

How a lambda is bracketed depends on its shape: a multi-line lambda uses the colon-argument
form, an underscore lambda is wrapped in parentheses, and a named-parameter lambda in braces.

## Variants

| Code | Message |
| --- | --- |
| `D2.1` | named-parameter lambda must be wrapped in `{…}`, not `(…)` (or use `f: x => …` since the lambda is last on the line) |
| `D2.2` | lambda is the last thing on its line; prefer `f: x => …` over `f { x => … }` |
| `D2.3` | multi-line lambda must use a colon-arg `f: x => …` form, not `<s>` |
| `D2.4` | anonymous (`_`-)lambda must be wrapped in `(…)`, not `<s>` |

## Resolution

Use the form the message names. The rule exists so that a reader can tell a lambda's shape
from its brackets alone.

This is a style rule rather than a correctness one. The house style is set out in
`doc/consequent-style.md`.
